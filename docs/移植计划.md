# HarmonyOS 移植计划

> 基线：Android 端功能清单见本目录 [Android端功能清单.md](./Android端功能清单.md)，源码位于 `D:\workspace\react\HuangGuo`。
> 已定路线（2026-11-14）：**UI 用 ArkTS + ArkUI 全原生重写；业务层（dx150 协议、下载引擎）用 Rust 编译到 OHOS，NAPI 桥接**。
> 当前工程状态：DevEco 空壳工程（API 6.1.1 / targetSdk 24，`com.encai.hg`，单 entry 模块），未初始化 git，未声明权限，无 native 目录。

## 0. 目标架构

```
HG/
├─ entry/                     ArkUI 界面层（全部页面）
│  ├─ ets/pages/              Home / Search / Category / Profile / Feed(播放) / Downloads / Posts ...
│  ├─ ets/player/             播放器封装（AVPlayer + XComponent）
│  ├─ ets/store/              全局状态（AppStorage/VolatileState + preferences 持久化）
│  └─ cpp/                    NAPI 桥接层（薄，只做参数转换）
├─ core/                      Rust workspace（从旧工程平移，几乎原样复用）
│  ├─ src/net.rs              请求层 + scope 路由（原样）
│  ├─ src/dx150.rs            加密协议（仅把 ring 换成纯 Rust 加密 crate）
│  ├─ src/media.rs            封面解密 + HLS 改写 + 缓存（原样，挂到本地 HTTP 服务）
│  ├─ src/download.rs         下载引擎（原样，落盘路径由 ArkTS 传入）
│  └─ src/mux.rs              TS→MP4 封装（纯算法，原样）
```

两个关键设计决策：

1. **本地媒体代理改用 127.0.0.1 HTTP 服务**。原方案靠 Tauri 自定义协议拦截 WebView 请求；原生重写后没有 WebView，但 `media.rs` 的处理逻辑（封面解密、m3u8 改写、分片透传）可以原封不动挂在 Rust 内起一个只监听 `127.0.0.1` 的 axum/hyper 服务上。AVPlayer 和 Image 组件直接用 `http://127.0.0.1:<port>/img?u=...` 这类地址，**media.rs 一行不用改**，也彻底绕开 ArkWeb 拦截的不确定性。
2. **加密库从 ring 换成 RustCrypto 纯 Rust 实现**（`p256` + `hkdf` + `aes-gcm`）。旧工程里封面解密和下载分片解密用的 `aes`/`cbc` 本来就是纯 Rust，只有 dx150 用了 ring（含汇编，对 `*-linux-ohos` target 支持不确定）。换掉后整个 Rust crate 零 C 依赖，交叉编译无风险，且加解密行为逐字节可控。

## 1. 阶段划分

### 阶段 0：工程基建（约 1 天）
- [ ] `git init` + 首次提交（现在还不是 git 仓库，越早越好）
- [ ] DevEco 中给 entry 添加 C++ 支持（自动生成 `cpp/` + `CMakeLists.txt`）
- [ ] 安装 OHOS Rust 交叉编译环境：`rustup target add aarch64-unknown-linux-ohos`，配置 DevEco 自带 native SDK 里的 linker（或用 cargo-ohos 类工具）
- [ ] Rust 侧建 `core/` crate（`crate-type = ["cdylib"]`），用 napi-ohos（napi-rs 的 OHOS 分支）暴露一个 `hello()`；ArkUI 调通显示返回字符串
- **验收**：真机/模拟器运行，界面显示 Rust 返回的字符串

### 阶段 1：协议层跑通（约 1–2 周，最高风险优先做）
- [ ] 平移 `dx150.rs`，ring → `p256`/`hkdf`/`aes-gcm`（握手、派生、seal/open 逐字段对照改写）
- [ ] 平移 `net.rs`（reqwest 在 OHOS target 可用；如遇问题退化为超集的 `rquest`/自带 client）
- [ ] 平移 `session.rs`：`session.json` 存到 `context.filesDir`（路径由 ArkTS 启动时传入），格式与 Android 完全一致
- [ ] NAPI 暴露命令：`boot / login / register / logout / me / feed / category / rank / search / video / play / posts / post / comments / like / collect / follow / commentSend`（签名与旧 `api.ts` 一一对应，前端调用代码可参考 `src/api.ts`）
- [ ] ArkUI 建一个**调试页**（不进正式导航）：列出 feed 标题、显示解密后的封面、搜一个关键词
- **验收**：调试页能看到真实列表数据 + 解密成功的封面图；登录/登出真实生效
- **风险**：dx150 细节（HKDF info 拼接、AAD、seq/ts 字段）——Rust 平移方式下风险最低，但改动 ring→RustCrypto 后要先用旧工程当对照组跑一遍同一接口，两边密文/明文一致才算过

### 阶段 2：媒体链路验证（约 3–5 天，第二个高风险点）
- [ ] Rust 内起 `127.0.0.1` 本地服务，挂上 `media.rs` 的 `/img /hls /seg` 处理器
- [ ] **Spike：AVPlayer 能否直接播上游的 AES-128 HLS**（经本地代理改写后的 m3u8）。这是全计划最大的未知数，越早验证越好
  - 能播 → 播放方案锁定 AVPlayer
  - 不能播 → 备选：Rust 侧分片预解密 + 本地伪流（下载后播放，牺牲边下边播）；或评估三方播放内核
- [ ] Image 组件走 `127.0.0.1/img` 加载封面，确认解密图正常显示
- **验收**：任意一部剧的任意一集可以完整播放到结尾；封面全部正常
- **风险**：AVPlayer 对 AES-128 HLS 的支持程度需实测；HTTP 回环地址若被安全策略拦，配置允许明文回环

### 阶段 3：骨架导航 + 首页信息流（约 1 周）
- [ ] 4 个 Tab（Tabs 组件：首页/搜索/分类/我的）+ `NavPathStack` 页面栈（对应旧 `store.tsx` 的 stack/push/pop）
- [ ] 首页 Feed：竖向 `Swiper`（对应 scroll-snap 整屏切换）+ 每页一个播放器实例；分页加载（10/页，倒数第 3 条预取，id 去重）
- [ ] 播放地址按 `videoId:ep` 内存缓存；播放即写观看历史（≤80 条）
- [ ] 右上角静音/搜索悬浮按钮；默认静音、音量记忆
- [ ] `onBackPress` 按 7 级优先级实现（对应功能清单 §2.3）
- **验收**：首页无限刷、上下切换流畅、切 Tab/返回行为与 Android 端一致

### 阶段 4：播放页完整版（约 1–1.5 周，交互最重的一页）
- [ ] AVPlayer + XComponent 封装：横竖屏自适应（宽>高 contain / 否则 cover）
- [ ] 手势系统（gesture 组合，对照清单 §3.2）：单击暂停（260ms 判定）、长按 380ms 2x + 上滑 64px 锁定（`vibrator` 震动反馈）、横拖 seek（时间浮层）、竖滑切换
- [ ] 底部可拖进度条（时间气泡、粗细变化）；倍速档 1/1.25/1.5/2 + 锁定胶囊
- [ ] 沉浸全屏层（应用内实现）+ 横屏视频舞台旋转
- [ ] 自动连播下一集、错误卡片重试、缓冲/暂停态 UI
- [ ] 右侧操作栏：关注、点赞（爆裂动画）、评论、收藏、下载三态图标、选集、分享（`@ohos.pasteboard` 复制链接）
- [ ] bindSheet 底部弹层：选集面板（正/倒序）、评论面板（分页 + 发表 + 未登录拦截）
- **验收**：交互逐条对照清单 §3.2–§3.4 过一遍

### 阶段 5：数据类页面 + 持久化（约 1 周）
- [ ] preferences 持久化：likes/favs/history/follows/muted/volume/searchHist（键结构与 `_app_v1` 对齐，方便以后两端互通）、主题
- [ ] 搜索页：历史 chips、热门题材、瀑布流结果（`WaterFlow` 组件）、加载更多
- [ ] 排行榜（3 个子 Tab + 指标条）
- [ ] 分类页：4 频道横向滚动 + 图文频道 + 频道详情页（排序/无限滚动）
- [ ] 图文帖列表 + 详情（HTML 白名单清洗逻辑需用 ArkTS 重写或简化为纯文本渲染——图文帖少时可选后者）
- [ ] 我的页：登录/注册卡、收藏/历史网格、设置、关于、清理缓存
- [ ] 主题资源化：`resources/base`（深色）+ `resources/light`（浅色）双 color.json，对应旧 CSS 变量方案
- **验收**：全部页面走查；杀进程重启后收藏/历史/主题/登录态均保留

### 阶段 6：下载引擎（约 1 周）
- [ ] 平移 `download.rs` + `mux.rs`（纯算法原样；落盘目录改为应用沙箱 filesDir）
- [ ] 任务管理 NAPI：`dl_add/list/pause/resume/retry/remove/verify`；状态经 ThreadsafeFunction 回调 ArkTS（对应 `dl://state` 事件），进度模型不变
- [ ] 下载页 UI：双子 Tab、进度/速度/分片、暂停/继续/重试/删除、`need_permission` 流程
- [ ] 已完成文件「保存到媒体库」：`photoAccessHelper` 写入系统图库视频（OHOS 没有公共 Download 直写，权限模型不同——以媒体库 API 替代）
- **验收**：完整下载一集 → 封装 MP4 → 媒体库可见可播；断网续传、杀进程恢复任务均正常

### 阶段 7：体验收尾 + 发布（约 3–5 天）
- [ ] Toast（`promptAction`，带图标）、页面转场动画、按压缩放动效
- [ ] 安全区适配（`getWindowAvoidArea`，对应 `--sat/--sab`）
- [ ] 启动自检探针（debug 构建下跑协议→媒体链路并输出日志）
- [ ] 应用图标/启动页、版本号对齐 1.0.1
- [ ] release 构建混淆、真机全量回归（对照功能清单逐节打勾）
- **验收**：对照《Android端功能清单》§2–§8 全部通过

## 2. 平台能力映射表

| Android/Tauri 侧 | HarmonyOS 侧 |
| --- | --- |
| Tauri command（invoke） | NAPI 函数（napi-ohos，async → Promise） |
| `hg://` 自定义协议 | Rust 内 `127.0.0.1` HTTP 服务 |
| hls.js（WebView MSE） | AVPlayer + XComponent（AES-128 支持需阶段 2 实测） |
| `dl://state` 事件 | NAPI ThreadsafeFunction → emitter/AppStorage |
| localStorage | `@ohos.data.preferences` |
| session.json / downloads.json | Rust 直写 `context.filesDir`，格式保持一致 |
| Android 返回键监听 | `onBackPress()`（UIAbility/Page 级） |
| `navigator.vibrate` | `@ohos.vibrator`（需申请振动权限或使用场景豁免项） |
| 系统下载目录 + 存储权限 | 应用沙箱 + `photoAccessHelper` 保存到媒体库 |
| env(safe-area-inset-*) | `getWindowAvoidArea` |
| CSS 变量主题 | `resources/base` 与 `resources/light` 双份 color.json |

## 3. 风险清单

| # | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 1 | AVPlayer 对上游 AES-128 HLS 的兼容性 | 播放方案可能推翻重来 | 阶段 2 最早验证；备选：Rust 预解密 + 本地伪流 |
| 2 | ring 不支持 OHOS target | dx150 编译不过 | 按计划换 RustCrypto 纯 Rust 实现，与旧工程对照验证 |
| 3 | reqwest/rustls 在 OHOS 的交叉编译 | 网络层受阻 | 纯 Rust 加密 + rustls 无 C 依赖，理论上可编；卡住则换 reqwest 退化配置或 OHOS http API 包一层 |
| 4 | Swiper 多实例播放器内存 | 快滑时卡顿/OOM | 维持旧策略：仅当前页挂播放器，邻页只放封面图 |
| 5 | 图文帖 HTML 渲染 | 原生无 DOM | 前期降级为纯文本；确有需要再引入富文本组件 |
| 6 | 媒体库保存的权限/审核模型 | 阶段 6 返工 | 提前在阶段 6 第一天做 spike |
